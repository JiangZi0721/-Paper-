## EvoOntology: A Self-Evolving Ontology Layer for Data Agents
    这个是针对数据智能体的，外部的数据和Agent接口存在Gap。agent只有SQL等一些检索工具，但是完全不懂字段在哪、业务含义，只能不断发送SQL试探。并且直接让agent读取原始的schema容易超出context，且充满无意义的缩写，也无法自适应对齐不同的agent。
1. 这个论文就是让agent理解业务含义，主动按需查询，同时让知识库随着经历自进化。于是把本体组织为一个MCP服务器。分三层：
    - 内容层：一张有类型的语义知识图，节点是语义概念term、约束规则constraint是、数据映射mappings、证据evidence；边就是term之间的关联、term和其它节点的引用链
    - 模式层：承接上述的语义知识图，存储节点的类型、边的类型、引用规则；
    - 工具层：agent能通过tool按需访问，返回相关term（tool-1）以及相关term的完整语义记录（tool-2）
2. 初始本体像普通agent一样试探性查询，找到对应字段、值分布等，将这些经过实际执行验证的候选概念提交，保证语义记录有证监局支撑，之后就是自进化：diagnose诊断失败原因->attribute到层级（内容、模式、工具）->对具体层级修改->新旧版本对比，好的才被接受。
3. 这个项目就是让数据智能体存储结构化的类型知识网络，可推理、可复用，不同模型建立的语义理解甚至不同，不能跨模型共享。
4. 这个项目的自进化在知识库。



## Calibrating Teacher--Student Discrepancy for On-Policy Distillation (Cal-OPD)
    依旧OPD，研究教师和学生之间的概率分布差异的形成原因。9-18的一篇论文里提到，特权信息没有实际提升蒸馏效果，甚至可能诱发教师产生更大的似然偏移，学生学不到东西，还过拟合了教师的系统噪声，所以训练效果差。
    关于特权OPD的论文目前有三篇，有一篇论文是让教师自己退休，学生就能超越教师；另一篇是说privileged info没用，第三篇是这个。

1. 教师自偏离TSD————privileged info下，学生学到的都是污染信息
    - 研究发现，给教师模型提供context干扰，对比无干扰情况，token的分布极不稳定，发生显著偏移；
    - 甚至输入正确和错误答案，两种情况的偏移方向、程度基本重合，说明privileged info没有让教师模型理解知识，只是教师模型自己因为扰动发生的偏移；
    - 进一步研究发现，TSD的概率主要集中在语气转折虚词上，数学符号之类的比较稳固。然而学生就会把这些语气词的晃动当作真理来拟合，导致文风的过拟合和长度失控。
2. 解决方法
    - privileged info不用来教学生，而是作为一个探针。用上述的正负对比干预，计算教师的偏移幅度，从而界定偏离摆动的盲区，切除这个盲区，提取真实校准残差，这样就能判断学生到底需不需要学习教师：
        - 学生的预测对数似然在禁区内：可以用教师的偏移解释，梯度不回传，不学习；
        - 禁区之外，学生真的落后或超越教师，将超出边界的部分梯度回传。
3. 从结果上来看，本项目丢失了1/3到1/2的原始信号，但是性能超越了使用100%信号的baseline。

## CodeMidas: Scaling Agentic Coding RL Environments from Code Itself
    传统RL需要海量具备确定性通过/失败验证信号的任务，但鲜有的只能从历史PR中获取，数量有限且语言单一，大模型还可能学过。这篇论文让agent仅凭开源项目的纯源代码，自主合成海量带有executable verifier的RL任务环境。
1. 步骤长这样：
    - agent读仓库，找到有显式io的公共接口，把这部分的核心实现切除，原实现作为reference，剩下的代码就是残缺的状态，agent撰写任务要求。需要装入dockers容器，如果不报错就是切除无效，直接淘汰
    - 测试就用原代码，源代码的真实输出作为assert。
    - 残缺代码和reference分别装在多个docker容器，前者必须报错，不然就是残缺不够，淘汰；后者必须100%通过，偶发性错误也要淘汰。
    - Rollout三连过滤审查，用agent对抗式的扫描错误，保证没有作弊；用前沿LLM求解，检测FP和FN，确保没有歧义；最终保留既有成功也有失败的，剔除简单题或者难题、坏题，确保梯度方差最大化
2. 这个项目就是让agent自己创造RL的学习资料自进化，中间经过严格审查确保高质量学习。

##  GraphSkillEvo: Evolutionary Optimization of Graph-Structured Agent Skills

    skill层面的。以往的skill以无结构纯文本存在，自进化的路径是总结提炼失败轨迹，生成更新补丁，追加或者替换文本，再进行评估。问题在于，随着reflection轮次增加，纯文本skill就冗长，没有分支逻辑，且现存方法只维护single candidate，贪心式单线修改，容易收敛，无法融合多个解法的优势。
1. 于是本论文将skill建模为图结构，节点为单一步骤的执行动作逻辑与操作指引，有向边为条件状态转移
2. 基于图结构，优化器就可以进行演化计算，通过种群机制维护多个候选技能图，通过演化算子（突变&交叉），对技能进行微调、增删（突变）和融合、拼接（交叉）。
3. 对于交叉算子，按适应度排名抽取亲本，后代与亲本竞争，保留Top进入下一轮，淘汰劣质变异。

## Grounded Skill Synthesis from Code at Scale for Agentic Intelligence (Code2Skill)
    当前问题：智能体在新领域中存在“缺少交互经验”的冷启动问题，真实环境交互合成成本太高，直接读文本说明又因为缺少代码实证而容易出错。本论文研究如何自动提取、合成并验证可跨任务迁移的高质量过程性技能。
1. 本论文的核心假设是：人类最高质量“过程性只是”在开源软件的代码库。
2. 本项目skill来自于高星开源项目，将精选代码单元转化为**原子操作**、**复合工作流**与**周期模式**的结构化记录，作为技能卡。
    随后在不提供源码函数体的情况下，让模型自己仅根据提取出的技能规范尝试逆向重写代码，再与真实源码进行跨视角行为比对，确保技能的完备性与可执行性；
    如果仅凭卡片就能准确还原出原代码的控制流、边界处理和核心断言，就证明这个技能卡片已经完全吸纳了代码中的过程性知识。
3. 这个项目类似于CodeMidas，都是从开源项目中提取有效信息，一个是交互轨迹，另一个是skill
