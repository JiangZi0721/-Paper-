## One to More, More to One: Category-Aware Iterative Expert Training for Software Engineering Agents (Logics-SWE)
**关键词**：多专家在策略MOPD，在线探索Rollouts

    强化学习的资料混合着很多类别，就有一种现象：模型在某些类别的任务性能上升，往往伴随其他任务的性能倒退（category see-saw）。于是本篇论文就研究每个类别分化出对应的专家，这样就不容易出现以上问题，具体如下：
1. 定义多维正交任务属性轴，对GitHub issues进行labeling
    - **SWE labeler** 标准化层次标签系统。
2. 本论文设计两阶段的演化架构
    - one to more：从同一个base模型分化出多个领域的专用专家，各自在自己的领域交替进行**RL探索+自身轨迹修复（RRE）**
    - more to one：将上述分化后训练好的专家作为teacher，进行OPD，即MOPD。

3. 一些其它算法
    - **带外推奖励（reward extrapolation）校准的在策略蒸馏**：当学生自身探索达到甚至能超越教师时，动态降低正则化的惩罚。
    - **Agentic-miniRL**
        - Leave-one-out：在同一任务采样的多条轨迹中，在计算优势函数时排除自身，当仅有1次较为罕见的成功时，传统GRPO的归一化会衰减奖励信号，赋予成功轨迹1.0的强优势，保留稀疏的成功信号
        - 在累加折扣回报的时候，减去k1散度惩罚保证 Policy Gradient 拥有严格无偏的 Score-function 梯度。
        - Turn-Aware Reduction：屏蔽环境输出的observation，按轮次平均后再轨迹平均，避免轨迹长短的干扰。
    - **RRE**:Refresh-Repair-Expand。只跑RL容易出内部遗忘，于是有
        - refresh:每轮RL，用当前模型在训练集上跑几次rollout
        - repair SFT：建立历史成功轨迹pool，对于能力退化的任务，给更高配额的历史成功轨迹进行replay SFT。
        - expand：将已经长我的任务移出预算，再抽取其它盲区任务继续训练。

## Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design
    Adobe研究的长程工具交互。
**问题** ：长程智能体（面向PS、illustrator的设计agent）没有确定性代码预言机（审美没答案）；且这些工业系统包含了大量的底层参数敏感的api工具，微调模型可能导致泛化受损，必须冻结基座模型权重；纯prompt工程在长程组合中容易幻觉和逻辑短路。
1. 本项目将自进化放在**自然语言程序性记忆库（skill bank）**上，形式上是一个可渐进式展开的skill，程序性记忆作为元素，是高阶的模块化工作流。
2. 自进化系统架构：
    - prompter：用户提出设计需求
    - solver：agent本体（检索技能->过滤工具->执行长程工具链->渲染图形）
    - grader：对照用户的要求逐条断言，输出失败诊断。
    - reflector：将失败诊断作用于skill的修改
3. 一些核心算法
    - **记忆widening**：agent检索不到任务对应的skill时，该任务将会打上标签，存入coverage pool，当该需求达到一定频次时，就汇总成功工具链与prompt，提炼候选skill
    - **记忆deepening**：当某个skill的执行评分低于阈值，reflector就需要接受失败诊断，并调取该skill在历史所有成功任务的序列、waypoint和思考过程，成功保留，失败为改进靶点，做精准微调。
    - **匹配重放门控**：放弃绝对分数，执行冻结上下文的随机乱序成对盲测，单项准入： ∄ prompt lost ∧∃ prompt won，保证没问题且至少获胜一次。
4. 从结果来看，发现单纯加新技能（widen）或单纯改老技能(deepen)都无法超越Base，二者结合发生质变。

##  1% of Tokens Can Be Enough: On Gradient Estimation in On-Policy Distillation (IER-OPD)
    在OPD中，以往让模型对整条轨迹 100% 的 Token 进行全量回传，其实绝大部分时间是在拟合纯随机采样的方差噪音；只要选出信噪比最高的少量Token，蒸馏效果就能追平甚至反超全量蒸馏。
    此事在**Cal-OPD**亦有记载，学生模型通常会学到教师模型因privileged info偏移产生的噪声。不过这篇论文的重点是噪声来源于抽样误差。某个 Token 即使在逻辑上非常有用，但如果单次采样算出的单步梯度方向由于偶然性与真实期望梯度严重偏离，就会把模型参数带偏。
1. 论文定义了信息效率比IER，作为信号与噪声的比值，IER越高，说明该token上的反向传播梯度具有越高的方向纯净度。具体推导比较复杂。
2. 落地算法
    - **Top-k候选近似**：计算全词表不现实，于是取学生 Top-K Logits、教师 Top-K Logits 与采样出的真实 Token 的并集构成候选集，在这个小候选集上softmax就很快
    - **双轴联合门控**：有了**梯度可靠性（reliability）**的指标**IER**，和**有用性（usefulness）**指标**TIP**，提出两套软逻辑算子：
    **reliability和usefulness在OPD中是正交的**
        - IER-OR：允许某一维度的极端优秀弥补另一维度的平庸
        - IER-AND：只有当这个token有用且梯度方向纯净时才放行
3. 结果证明，在包含长思维链的推理任务中，传统的有用性指标（TIP）在小预算下甚至会学崩；而加上 IER-AND 严格过滤掉带有思维幻觉的采样噪声后，模型能力显著提升。
4. 在9-21的Cal-OPD中，证明了一些带转折的语义虚词是极大的噪声，让学生模型过拟合教师的语气之类，在IER中，也说明了虚词的杠杆因子L(a)采样噪声极大。**Cal-OPD的解决办法是划定禁区，虚词落在禁区内就直接阶段；IER-OPD则是通过计算得到噪声虚词的IER趋近于0，从而否决。**

## FRAUDSkill: Structured Frozen-Weight Skill Optimization for Audio Anti-Fraud Detection
    Act和Tool领域的。针对**反欺诈**长程多阶段决策严苛、模型微调容易灾难性遗忘，提出**首个针对冻结权重音频大模型的结构化外置技能自进化框架**。
    目前的自动化prompt/skill演化算法追求生成语言的多样性和连贯性，但在需要严格规范语言的反欺诈场景中不适合。这个项目就决定冻结模型参数，仅演进外部结构，
1. 一些核心算法
    - **轨迹因果解耦（Trajectory-Level Diagnosis）**：如果上游某一步发生错误，下面的步骤直接跳过，这样可以直接diagnose到错误的定位，critic模型在错误样本batch上生成reflection，editor据此产生候选程序变异领域，在验证集上通过beam search维持高质量候选池。
    - **确定性闭集标签投影**：大模型在复杂音频中容易给出语义高度相关但非标准的词汇，对标准的恒等映射，对无歧义的做规范化，对其他的强行置为错误/惩罚，杜绝幻觉扩散
    - **路由规范化**：下一步的上下文输入不再接收上一轮未经处理的自由文本，而是强制接收规范化后的基准历史（Canonical History），如果前一步判断为normal，下一步固化为NA，防止后续画蛇添足；如果判定为INV（欺诈），则下游直接认定欺诈。
    - **互补多路径推理**：不同程序在不同route和欺诈类型上具有错误互补性，系统发挥这些互补作用，并通过平衡选择，保护小概率欺诈小类样本。
2. 这个论文是针对agent下游任务为高风险严肃业务的改进，不微调（不容易灾难性遗忘），外挂可进化，动作出口由**投影算子**锚定。

##  ActGov: Governing LLM Agent Actions via Policy-Constrained Validation
    安全领域的，针对prompt注入。大模型可能被越狱，静态黑名单又限制agent的动态自适应能力。于是本项目建立规则化的防御机制。
1. 一些核心算法
    - **离线SMT形式化反例验证**：上述LLM提议的策略需要经过Z3数学验证，Z3会穷举合法输入找到LLM策略的漏洞，有反例则打回，以上过程在离线阶段进行。
    - **递进式授权**：计算任务所需最小特权工具子集+禁止违背安全公理+动态的业务约束
    -**二维正交状态模式**：防止自然语言的歧义和幻觉，将上下文投影为**形成（定义数据如何产生）+语义（覆盖7个安全维度）**二维空间，其中LLM不具有决策权，仅作为特征提取器，作为策略评估依据。
ActGov作为门控，只需根据预编译的策略+二维的信息做布尔求值，执行延迟极低，无需在线调用重型求解器。
2. 从结果来看，本项目几乎拦截了所有prompt注入，且正常任务完成率依旧维持。
3. 本项目证明了形式化方法SMT+LLM的互补性与可行性
