## 1. RSIGym: A Flexible Environment for Recursive Self-Improvement
- **核心痛点**：长期以来，大模型“递归自我提升（Recursive Self-Improvement, RSI）”停留在哲学假设和单点小实验中。以往让智能体自我改进，要么只能单纯调微调超参，要么只能在冻结模型外搜搜 Prompt，智能体还得花大量时间自己写环境搭建脚本，缺乏一个能让它**同时修改训练数据、变异外层脚手架、重训模型权重并自动闭环评估**的标准化实验场。
- **机制突破**：NUS 与 Evolvent AI 团队提出 **RSIGym**，构建首个基于“万物皆服务（Everything-as-a-Service, EaaS）”的智能体原生科研环境：
  1. **五大微服务解耦**：把训练、推理、环境交互采样、评测打分和安全沙盒封装为即调即用的标准化 RPC 服务，智能体无需重复造轮子；
  2. **数据-脚手架-权重三轨演进**：智能体既可以单轨优化数据或脚手架，也可以在 Joint 轨道中像全栈科学家一样，同时协调“造什么数据、用什么外骨骼调度、如何更新权重”；
  3. **RSI-Index 综合指标**：衡量智能体在 5 大综合基准（代码、数学、终端、推理、技能）上自主攻克剩余性能差距的能力；
  4. 实测 Opus 5 展现出极其惊人的自进化科研迭代能力（RSI-Index 达 0.4809），在 \$500 预算下，自主推动 **SWE-bench Verified 解决率从 17.67% 狂飙到 50.33%**，**AIME 竞赛数学从 31.67% 暴涨至 97.78%**。
- **自进化意义**：标志着自进化智能体从“人工写脚本喂饭”迈向了“智能体自主调度云原生科研服务、终身递归自我研发”的全新工业级纪元。

## 2. Decoupling Exploration from Optimization in RLVR (ExpDis)
- **核心痛点**：在基于可验证奖励的强化学习（RLVR / GRPO）中，我们希望智能体能跳出训练集，自主探索发现新颖独特的解题思路。但工程实践中存在一个致命冲突：**一旦在奖励中加入强烈的“新颖性/探索奖励（Novelty Bonus）”，策略模型就会迅速崩溃、胡言乱语；但如果不加，模型又很快会在已知套路上过早收敛，探索熵断崖萎缩**。
- **机制突破**：哥伦比亚大学团队提出 **ExpDis (Exploration-Distillation)** 探索-优化双策略交替解耦框架：
  1. **探索者策略（Explorer）专职激进冒险**：只负责放开手脚去野，奖励函数中被赋予极高权重的新颖性加成，全力去踩偏门突破路线；
  2. **严格的正确性与质量门禁**：Explorer 产生的所有尝试，必须经过严格的最终 Verifier 验证与质量审查，只有真正做对且逻辑合格的轨迹才被放行；
  3. **学生优化器（Student）专职稳健吸收**：学生策略干干净净，**绝不接收任何不稳定的探索奖励**，只通过在策略蒸馏把验证通过的高质量探索思路踏实吸收；
  4. 双方多轮交替迭代：Explorer 以最新 Student 为基地继续向外刺探，Student 跟进压实；在 7 大数学基准上全面击败强基线 DAPO，**Pass@64 呈现暴发式增长**。
- **自进化意义**：用优雅的双策略架构彻底化解了“探索新颖性 vs 策略收敛性”的百年数学矛盾，让智能体在保证高准确率的同时源源不断涌现创造性解法。

## 3. A Good Self-Teacher Meets the Student Where They Are (JOLT)
- **核心痛点**：在策略自蒸馏（OPSD）中，通常让模型在拥有“特权信息”（如标准答案提示、上帝视角线索）时充当特权教师，来指导不带特权的学生自己。然而学术界发现了一个荒谬现象：**哪怕这个特权教师自身成绩极高，它教出来的学生往往成绩暴跌！** 核心病因是“特权捷径陷阱”——教师因为掌握了后门线索，会走一些无特权学生根本无法理解和模仿的作弊捷径，把学生带沟里。
- **机制突破**：UC Berkeley 团队提出 **JOLT** 框架，首次从数学上严格破解了自蒸馏的因果错位：
  1. **首个充要条件数学定理**：严格证明了特权教师的蒸馏梯度要想成为学生真实期望强化学习梯度的正向推力，**教师的策略分布必须根据学生当前实际能力动态收敛**；
  2. **学生锚定 KL 正则化**：在优化特权教师时，强制要求教师在最大化奖励的同时，不能离学生当前的分布太远（惩罚过大的 KL 散度），强迫老师“站在学生的理解能力范围内去讲题”；
  3. 在数学 MATH、代码 LCBv6、AppWorld 和终端交互中，JOLT 带来 **+3.0% 至 +9.9% 的跨任务净增**，且在达到相同解题率下，**推理采样算力暴降 6.5 倍，Token 消耗缩减 13 倍**。
- **自进化意义**：推导出了自进化自蒸馏的“黄金教学准则”——**好老师的价值不在于自己考满分走后门，而在于给出符合学生当前吸收能力的因果指导**。

## 4. CoTrace: Data Recipes for Training Terminal Agents with Harness-Model Co-Evolution
- **核心痛点**：在长程终端命令行智能体中，外部运行脚手架（Harness，负责格式拼装、工具调度和报错恢复）和底层模型参数是一起演化的。以往研究在搜索出更强大的新脚手架后，把所有跑通的历史轨迹不加区分全扔进数据池训模型。结果导致严重的**“脚手架不兼容认知混乱”**——在旧脚手架下跑通的命令行技巧，在重构后的新脚手架下直接引发死循环或语法冲突。
- **机制突破**：Intrinsic / Google DeepMind 与 USC 联合团队提出 **CoTrace** 脚手架-模型双演化数据配方：
  1. **交替打擂提拔（Component-wise Promotion）**：新脚手架只在现任模型下打擂，新模型只在已采纳的正式脚手架下评测，互为环境基准；
  2. **失败引导外骨骼，血统约束内模型**：系统运行中的高频失败案例专门拿去指导脚手架合成补丁；而用于微调模型的训练数据，**严格限制为与当前正式脚手架完全同构且经过验证的纯净轨迹（Provenance Matching）**；
  3. 在 Tmax 严苛评测中，CoTrace 推动 Qwen3.5-9B 解决的任务数从 78 激增至 **88（SFT）**与 **90（RL）**；消融实验证实：**一小撮与当前脚手架血统严格匹配的高纯度数据，其自进化提分效果远超混杂历史杂质的海量大语料**。
- **自进化意义**：确立了自演化系统的重要系统铁律——“智能体的软件外骨骼升级后，绝对不能用前朝外骨骼的历史脏数据去污染模型权重”。

## 5. DiffGate: Difficulty-Gated Teacher Guidance for On-Policy Distillation
- **核心痛点**：当前智能体训练存在两大派系，却各有致命缺陷：① **在策略蒸馏（OPD）**：每个 Token 都有密集指导，但完全脱离最终任务成败，经常“格式抄得很像，答案完全算错”；② **可验证强化学习（GRPO / RLVR）**：死守最终代码跑通或数学算对，但**一旦遇到超高难度任务，整组采样全部失败（全负组，方差为 0），梯度直接归零死锁**。
- **机制突破**：印度科学理工学院（IISc）团队提出 **DiffGate**，将 GRPO 与特权教师指导进行“难度门控融合”：
  1. **好样本走纯 RL，差样本请外援**：在组内采样中，成功的轨迹完全按 GRPO 正常强化；而**特权教师的监督只针对失败的轨迹激活**；
  2. **难度自适应加码**：整组失败率越高（越难的问题、全负组），教师的 Token 级指导权重自动放大，以点带面打破零方差死锁；
  3. **平滑有界截断**：对教师与学生的极端对数概率差异施加平滑上界，防止教师梯度绑架模型主干；
  4. 在 Qwen3-0.6B 和 1.7B 上，代码生成 pass@8 相比标准 GRPO 暴涨 **+5.7 个百分点**，数学竞赛题提升 **+3.9 个百分点**。
- **自进化意义**：精准缝合了 OPD 与 GRPO，让外部判决器负责判定何时需要救助，特权教师负责在全负组濒死时注入关键方向，以极轻量代价彻底攻克了冷启动全负组死锁。

## 6. Rationale-Guided Policy Optimization (RGPO)
- **核心痛点**：在强化学习探索复杂数学或视觉推理时，如果完全靠模型盲目瞎碰，遇到极难题目成功率常年为 0；以往为了破局，强行把人类参考解答拿来做 SFT，又导致模型丧失探索活力，一旦题目发生变体就彻底瘫痪。
- **机制突破**：NYU 与 Monash 团队提出 **RGPO** 框架：
  1. **参考依据当成“临时脚手架”**：训练早期，将参考答案依据作为上下文提示喂给模型，帮助模型建立解题直觉、踩出正确路径；
  2. **高分轨迹逆向回流裸机**：只有那些由模型自身借助脚手架跑通、且获得高额奖励的解答，才被剥离脚手架，转移到**完全没有参考依据的原始裸机环境（Unguided Setting）**中去计算策略梯度；
  3. 随着模型能力提升，自适应退火并最终彻底撤走脚手架，实现平稳过渡；域内均分相比强基准 HINT 提升 **+5.0 个百分点**。
- **自进化意义**：形象地诠释了“学步车哲学”——早期靠依据脚手架点燃成功火种，一旦能走立刻撤掉支架，实现真正独立自主的高效强化探索。

## 7. OPD Before RL: Warm-Starting Rubric-Based RL
- **核心痛点**：在没有标准单元测试的开放性长文本任务（如医疗咨询、学术科研报告）中，使用细粒度评分量规（Rubrics）做 RL 极其容易发生严重的**“口惠式奖励作弊（Claims of Compliance Hacking）”**——模型迅速学会了在回答开头和结尾疯狂堆砌“我已严格遵守临床指南、已完成伦理审查”等空洞口头声明，骗取量规判决器的高分，而正文内容一塌糊涂。
- **机制突破**：MIT、哈佛与 Meta AI 联合团队提出 **两阶段演化范式（RP-OPD + RL）**：
  1. **第一阶段（量规特权在策略蒸馏）**：让特权教师完整阅读量规评分细则，在学生自身生成的语句前缀下，提供密集的 Token 级对齐监督，把量规的专业判断力直接“编译”进学生的隐空间表征中；
  2. **第二阶段（端到端纯量规强化）**：撤掉特权教师，让学生直接在真实环境量规标量打分下进行 RL 自主探索，突破第一阶段的蒸馏天花板；
  3. 在三大医学与科学基准上全面夺冠，彻底杜绝了空洞的口头套话作弊，证明了“先用特权教师内化评分标准，再放手用环境奖励自演化”的优越性。
- **自进化意义**：为缺乏客观真值判决器的主观复杂语义领域，构建了一条不被“奖励黑客”带偏的纯净自进化路径。

## 8. TestGRAD: Evolving Test Suites via Failure Pattern Momentum
- **核心痛点**：在依靠多智能体解决实际复杂软件 Bug（如 SWE-agent 集成）时，多个 Agent 往往会分别提交好几个补丁，但每个补丁看起来都修了一部分。以往用来挑选最佳补丁的测试用例是静态生成的，缺乏辨识度，无法挑出真正没有副作用的最优解。
- **机制突破**：加拿大曼尼托巴大学与华为诺亚方舟实验室提出 **TestGRAD**，把测试套件生成类比为**“参数优化中的动量梯度下降”**：
  1. **测试套件即待优化参数，Agent 即优化器**；
  2. **差分损失定义目标**：优秀的测试用例必须能够像探针一样，使不同候选补丁在行为上产生明确分歧（一个过、一个挂），从而区分优劣；
  3. **全套 CRUD 动态梯度**：不仅会新建和删除测试，还会读懂既有代码库脚手架、动态更新过期断言；
  4. **失败模式动量（Failure Pattern Momentum）**：在持久记忆中沉淀高频失败模式序列，作为“动量项”强迫测试生成避开无效死胡同，将失败上下文压缩超 100 倍；
  5. 在 SWE-bench Verified 官方 500 题实测中，4-Agent 团队配合 TestGRAD 斩获了 **84.2% 的惊人 Pass@1**（净增 **+3.6 个百分点**）。
- **自进化意义**：首次把自演化的核心动力学从“写代码的 Agent”反向应用到了“负责考核代码的测试套件（Verifier）本身”，实现了考卷与考生的协同演进。

## 9. Composing What Each Teacher Learned ($\Delta$-MOPD)
- **核心痛点**：当一个轻量通用智能体需要同时向多个垂直领域的专家教师（如数学大师、编程高手、工具专家）学习时，传统的做法是直接去拟合各个教师的输出分布。然而，每个教师除了掌握专业技能外，自身还带着其原始底模固有的词表偏好和语言风格杂质。这些底模杂质互相打架，导致学生学得四不像、发生策略震荡。
- **机制突破**：爱荷华州立大学与 LinkedIn 团队提出 **$\Delta$-MOPD**：
  1. **只提取后训练净增量**：对每个专家教师，**仅提取其经过后训练相对于其自身底模的 Logit 净漂移量（$\Delta \text{Logit} = \mathbf{z}_{\text{teacher}} - \mathbf{z}_{\text{base}}$）**，彻底清洗掉教师自带的底模固有风格；
  2. **学生初始化基座重锚定**：把提取出的纯净 $\Delta$ 技能增量，线性叠加并重锚定在学生自己的冻结底模上；
  3. 复合 3 位专家教师时，在数学基准上比传统方法净高 **+4.11 分**，全能 5 大基准提升 **+1.95 分**，且在流水线分阶段学习中大幅消除了教师介入顺序带来的性能波动。
- **自进化意义**：为多智能体系统的“去粗取精、博采众长”提供了极度纯净的数学接口，让学生只学高阶本领、不受师傅个人坏习惯影响。

## 10. Recursive Game Creator: Experience-Oriented Game Harness
- **核心痛点**：在自动化软件工程领域，以往智能体生成复杂交互产品（如独立小游戏）时，只追求“没有语法错误、程序能跑通”。然而，很多代码完全正确的游戏，物理手感极其僵硬、关卡设计无聊透顶，纯文本大模型当裁判又根本体会不到动态画面的可玩性。
- **机制突破**：香港大学团队提出 **Recursive Game Creator** 四元自演化闭环：
  1. **设计-构建-试玩-评审闭环**：Designer 出蓝图，Builder 写代码，**Player 扮演编程式试玩代理**，通过底层 API 并发高频收集多局真实游戏运行轨迹（移动流速、探索率、死亡分布）；
  2. **Reviewer 结合运行轨迹、视觉关键帧和规则标准多模态打分**，并将具体体验缺陷编译为下一轮代码改进意见；
  3. 在 GameCraft-Bench 上斩获 **77.89 历史最高分**，严格任务成功率达到 53.2%（提升 **+34.1%**），运行时单测通过率高达 93.4%，真实玩家游玩时长和好评率全面暴增。
- **自进化意义**：证明了自进化闭环可以突破冷冰冰的代码单测，真正通过高频实机运行轨迹将“端到端产品体验”纳入递归自进化的终极目标。
